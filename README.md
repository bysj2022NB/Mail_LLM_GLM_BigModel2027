## 1. 系统概述

MailGuard 是一个融合传统机器学习、大语言模型复核、QQ 邮箱接入和可视化管理的垃圾邮件检测系统。系统围绕“模型训练—模型评测—模型发布—邮件检测—AI 复核—安全处置”构建完整闭环，不仅给出垃圾邮件或正常邮件标签，还会展示垃圾概率、风险等级、判断依据、主要特征、处理建议和模型版本等信息。

系统后端基于 Python 3.13 与 Flask，前端基于 Vue 3 与 TypeScript，数据和任务状态使用 SQLite 持久化。模型训练、批量检测、QQ 邮件拉取和 AI 复核等耗时操作交由后台 Worker 执行，页面通过进度条和阶段文字持续反馈执行状态，避免长任务阻塞 Web 请求。

系统支持管理员与普通用户两类角色。管理员负责模型、LLM 节点、用户、审计日志和全局策略；普通用户可以检测邮件、绑定自己的 QQ 邮箱、查看邮件详情和主动发起 AI 复核。邮件正文、附件、检测记录及邮箱配置按用户隔离，管理员不能通过业务接口查看其他用户的邮件正文或密钥。

## 2. 建设背景与目标

传统垃圾邮件过滤器通常只返回一个简单标签，用户难以理解模型为何做出判断；单独依赖大语言模型又存在调用成本、网络波动和第三方接口不可用等问题。MailGuard 将二者组合：本地机器学习模型负责快速、稳定的第一轮检测，大语言模型只在用户主动点击后提供第二视角。

系统主要建设目标如下：

1. 建立可复现的中文垃圾邮件训练和评测流程。
2. 支持手动输入、批量文件及 QQ 邮箱三类检测入口。
3. 通过可视化界面解释模型结果和任务进度。
4. 使用大语言模型对机器学习结果进行结构化复核，并支持多节点故障转移。
5. 在密钥加密、权限隔离、HTML 清洗、附件下载和邮件删除等环节落实安全控制。
6. 为后续增量学习、更多邮箱协议和多机部署保留扩展空间。

## 3. 目标用户与应用场景

| 用户类型 | 主要需求 | 可使用功能 |
| --- | --- | --- |
| 普通用户 | 判断单封或多封邮件是否安全 | 内容检测、批量检测、检测历史、QQ 邮箱、AI 复核、个人中心 |
| 系统管理员 | 维护检测能力和系统策略 | 模型训练、模型评测、模型发布、LLM 管理、用户管理、审计日志、系统设置 |

典型应用场景包括个人邮箱风险筛查、中文营销邮件识别、可疑邮件二次复核、机器学习课程设计演示，以及邮件分类算法的对比评测。

## 4. 系统总体架构

```mermaid
flowchart LR
    U[普通用户 / 管理员] --> V[Vue 3 可视化客户端]
    V -->|REST /api/v1| F[Flask API 服务]
    F --> A[认证、RBAC 与审计]
    F --> S[业务服务层]
    S --> D[(SQLite 数据库)]
    S --> R[runtime 运行目录]
    F --> Q[SQLite 持久化任务队列]
    Q --> W[后台 Worker]
    W --> M[机器学习训练与预测]
    W --> I[QQ IMAP 邮件拉取]
    W --> L[LangChain / OpenAI 兼容 LLM]
    M --> R
    I --> R
    L --> D
```

系统采用前后端分离与分层设计：

- 表现层：Vue 3 单页应用负责路由、表单、表格、图表、弹窗和进度反馈。
- 接口层：Flask 提供统一的 `/api/v1` REST API、权限校验和错误响应。
- 业务层：封装数据集解析、模型预测、MIME 解析、邮箱同步、AI 复核和密钥服务。
- 任务层：使用 SQLite 持久化任务队列处理训练、批量检测、邮件拉取及 AI 复核。
- 数据层：SQLite 保存业务数据，`runtime` 保存模型制品、邮件缓存、附件、上传和日志。

开发环境可以通过 `backend/run.py` 同时启动 API 和内嵌 Worker；正式部署可以使用 Waitress 提供 Web 服务，并独立运行 Worker。

## 5. 系统创新点

### 5.1 本地机器学习与大模型协同判定

系统先使用本地模型完成低成本、低延迟的垃圾邮件检测，再由用户主动触发 LLM 复核。AI 复核不会覆盖原始 ML 结果，而是以并列方式展示“是否同意 ML、复核置信度、风险依据和建议动作”，保留两种判断视角。

### 5.2 面向中文历史邮件的数据泄漏抑制

训练管线不仅进行普通随机切分，还将邮件正文作为统计模型的主要输入，并排除发件人和主题字段，降低历史发送者、固定主题等捷径造成的虚高指标。同时按照主题模板分组后进行分层切分，保证训练集、验证集和测试集之间的模板组不重叠，使评测更接近真实泛化能力。

### 5.3 多 LLM 节点顺序回退

管理员可以配置多个 OpenAI Chat Completions 兼容模型，设置访问顺序、超时时间和启用状态。复核时按优先级依次调用；当节点出现超时、鉴权失败、网络错误或返回结构不合格时，系统自动切换到下一节点，并记录每次尝试的结果和延迟。

### 5.4 邮箱、检测、复核和处置的一体化闭环

系统能够从 QQ 邮箱拉取当天、近三天或近七天邮件，在邮件列表中执行单条或一键 ML 判定，再发起单条或一键 AI 复核。用户可以在详情页查看安全 HTML、纯文本、头信息、附件和 ML/AI 对比，并在满足服务器能力与全局策略时将垃圾邮件移动到“已删除”文件夹。

### 5.5 可恢复的异步任务与真实进度反馈

训练、批量检测、邮件拉取和 AI 复核都保存为持久化任务。Worker 持续上报心跳、当前阶段、百分比和错误原因；页面轮询真实任务状态，而不是使用虚假的前端计时动画。服务异常后可识别陈旧任务并进行恢复或重试。

### 5.6 全生命周期模型管理

模型具有排队、运行、就绪、已发布、失败、已取消和已删除等状态。系统同一时刻只允许一个已发布模型，新模型发布时会原子取消旧模型发布；历史检测结果保存模型名称、版本、算法和阈值快照，不会因模型更新而失去可追溯性。

### 5.7 安全与可解释性共同设计

邮件 HTML 会删除脚本、表单、事件属性和危险资源，并在沙箱 iframe 中展示；附件经过路径隔离、随机命名、SHA-256 计算、危险扩展名阻止和强制下载处理。QQ 授权码与 LLM API Key 使用加密主密钥保护，敏感信息在列表和日志中保持脱敏。

## 6. 系统核心功能

### 6.1 登录、注册与个人中心

- 支持用户名密码登录、手机短信验证码登录和用户自助注册。
- 支持短信验证码验证后重置密码，重置成功会使旧会话失效。
- 个人中心可以直接修改昵称和登录手机号，无需短信验证，也可以清除手机号。
- 支持修改密码、明暗主题切换及个人检测数据概览。

### 6.2 可视化仪表盘

- 展示今日检测数量、近七天垃圾邮件数量、AI 复核或邮箱状态、当前模型 F1。
- 使用 ECharts 展示当前用户近七天总检测量和垃圾邮件趋势。
- 支持加载、失败和空数据状态，并提供可访问的数据表作为图表替代。
- 展示当前发布模型、服务状态和近期检测记录。

### 6.3 模型训练

- 自动读取 `dataset/full/index` 中的 64,620 封 RFC 822 邮件。
- 支持字符级 TF-IDF + 逻辑回归，以及 TF-IDF + TruncatedSVD + 随机森林。
- 解析 GB2312、GBK、UTF-8、Base64、Quoted-Printable、纯文本和 HTML 邮件。
- 执行正文规范化、内容去重、模板分组以及固定随机种子切分。
- 页面按秒刷新训练进度，显示 MIME 解析、切分加载、特征构建、分类器训练、评测和制品保存阶段。
- 支持取消任务和删除已结束的训练任务记录。

### 6.4 模型评测与管理

- 展示准确率、平衡准确率、精确率、召回率、F1、特异度、ROC-AUC 和 PR-AUC。
- 展示混淆矩阵、ROC 曲线、Precision-Recall 曲线、阈值权衡、分类别指标及主要特征。
- 展示训练耗时、P50/P95 单封预测延迟、模型大小、数据集指纹和评测协议。
- 支持模型发布、取消发布、阈值调整和删除保护。

### 6.5 手动内容检测

- 用户可以输入邮件主题、发件人和正文。
- 返回垃圾/正常标签、垃圾概率、置信度、风险等级和模型快照。
- 提供内容摘要、可解释信号、风险依据和处置建议。
- 检测完成后可直接发起 AI 复核，并在页面展示复核进度和结果。

### 6.6 批量检测

- 支持 CSV、JSONL，以及包含 TXT/EML 文件的 ZIP 压缩包。
- 后台异步解析和检测，实时显示已处理数量、百分比、垃圾/正常数量和当前阶段。
- 支持查看任务内每封邮件的检测详情，并针对指定记录发起 AI 复核。
- 支持导出 CSV 结果和删除已结束的批量任务记录。
- 对 ZIP 路径穿越、异常压缩比、成员数量和解压后大小进行限制。

### 6.7 检测历史

- 按来源、标签和关键词筛选当前用户的检测记录。
- 支持单条删除、勾选批量删除和结果导出。
- 详情使用弹窗展示邮件快照、ML 解释、模型信息和 AI 复核历史。
- 未进行 AI 复核的记录可以直接在详情弹窗中发起复核。
- 用户可以提交误判反馈，为后续模型迭代提供依据。

### 6.8 QQ 邮箱中心

- 每个用户可以绑定多个 QQ/Foxmail 邮箱，授权码加密保存。
- 使用 `imap.qq.com:993` 和 TLS 拉取收件箱，不使用 SMTP 发送邮件。
- 支持当天、近三天、近七天拉取范围，并使用 UID、UIDVALIDITY 和文件夹实现幂等导入。
- 拉取范围与列表展示范围相互独立。
- 邮件列表支持清空本地缓存、单条/一键 ML 判定和单条/一键 AI 复核。
- 清空本地缓存不会删除 QQ 邮箱服务器上的邮件，并会同时清除关联 ML/AI 状态。
- 邮件详情支持纯文本、安全 HTML、图片、邮件头、附件和 ML/AI 对照展示。

### 6.9 AI 复核与 LLM 管理

- 使用 LangChain `ChatOpenAI` 调用 OpenAI 格式兼容接口。
- 管理员可以添加、编辑、删除、启用、测试和排序 LLM 节点。
- 节点测试展示测试状态、最近测试时间和响应延迟。
- AI 返回结论、置信度、一致性、摘要、风险依据、可疑特征和建议动作。
- 邮件正文被明确标记为不可信数据，提示词要求模型忽略正文中的指令，降低提示注入风险。
- 仅在用户主动确认后向外部模型发送主题、发件人、正文和 ML 结果；附件不会发送。

### 6.10 用户、审计和系统设置

- 管理员可以搜索用户、编辑昵称与手机号、调整角色以及启用或禁用账户。
- 系统保护最后一个启用中的管理员，避免被禁用或降级。
- 审计日志记录操作人、动作、资源、结果、时间和请求 ID。
- 系统设置支持全局邮件移动开关、高置信阈值、上传保留期、审计保留期和邮件缓存策略。

## 7. 数据集与模型设计

### 7.1 数据集概况

首版训练只使用 `dataset/full/index`，`dataset/delay/index` 作为未来增量学习扩展，不进入当前训练管线。

| 指标 | 数值 |
| --- | ---: |
| 原始索引邮件 | 64,620 |
| 垃圾邮件 | 42,854 |
| 正常邮件 | 21,766 |
| 重复内容 | 4,149 |
| 去重后训练/验证/测试 | 42,327 / 9,072 / 9,072 |
| 数据路径有效率 | 100% |

数据集包含部分空正文和损坏编码邮件。系统不会静默丢弃这些问题，而是在数据质量报告中统计空正文、替换解码和容错解析数量。

### 7.2 当前模型基线

以下数据来自当前系统数据库中已完成的严格测试集评测，判定阈值均为 0.72：

| 模型 | 状态 | Accuracy | Precision | Recall | F1 | ROC-AUC | P50 延迟 | 制品大小 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符级 TF-IDF + 逻辑回归 | 已发布 | 92.53% | 99.73% | 88.64% | 93.86% | 97.25% | 0.46 ms | 约 1.90 MB |
| TF-IDF + SVD + 随机森林 | 就绪 | 92.39% | 99.75% | 88.42% | 93.74% | 96.83% | 20.43 ms | 约 72.13 MB |

逻辑回归在当前数据上具有略高的 F1、更低的预测延迟和更小的模型体积，因此被选为当前发布模型。较高精确率与相对较低召回率反映了系统偏向减少正常邮件误报的取舍，不能只用单一准确率评价模型。

## 9. 安全设计

1. 身份安全：密码使用 Argon2id 散列，会话 Cookie 设置 HttpOnly 和 SameSite，修改密码或禁用用户会使相关旧会话失效。
2. 权限隔离：接口统一执行登录、管理员权限和资源所有权校验，普通用户只能访问自己的邮件、附件和检测记录。
3. 密钥保护：QQ 授权码和 LLM API Key 使用 Fernet 加密后存入 SQLite，加密主密钥只通过环境变量加载。
4. 邮件展示：HTML 删除脚本、表单、事件属性等危险内容，并放入带 CSP 的沙箱 iframe；远程图片默认加载但使用无 Referrer 策略并提示隐私风险。
5. 附件保护：单附件限制 20 MB，危险扩展名禁止下载，存储使用随机文件名并进行路径和所有权校验。
6. AI 安全：邮件内容只被视为不可信数据，不执行邮件中的指令，不访问邮件链接，也不请求或保存大模型隐藏思维过程。
7. 邮件处置：删除功能默认关闭，实际操作为 IMAP MOVE 到“已删除”文件夹，不执行不可恢复的永久删除。
8. 审计追踪：关键配置、用户状态、模型发布、邮件移动和 AI 调用都保留审计或尝试记录。

## 10. 可视化与交互设计

系统采用安全、可信的数据控制台风格，以深蓝色为主色，红色表示高风险，琥珀色表示警告，同时提供暗色主题。主要交互遵循以下原则：

- 所有耗时操作展示加载状态、百分比或阶段说明。
- 风险状态同时使用图标、文字和颜色，不依赖颜色单独表达。
- 表格支持空状态、错误恢复、筛选和响应式布局。
- 删除、AI 外发和远程邮件移动均要求明确确认。
- 主要按钮具备禁用和防重复提交状态。
- 支持键盘焦点、44 px 交互区域、减少动画偏好及 375 px 至 1440 px 响应式布局。

## 13. 当前边界与后续扩展

当前版本定位为本机或局域网单机系统，API、Worker 和 SQLite 位于同一台机器。首版只拉取 QQ 邮箱收件箱，不发送邮件，不自动定时拉取，也不分析附件正文。

后续可以扩展：

- 使用 `dataset/delay/index` 实现增量学习和模型漂移监控；
- 接入更多 IMAP 邮箱服务商；
- 增加定时拉取、通知和人工审核工作流；
- 将任务队列迁移到 Redis/Celery，将数据库迁移到 PostgreSQL；
- 增加附件 OCR、恶意文件扫描和 URL 信誉分析；
- 增加模型在线监控、反馈闭环和 A/B 发布机制。

## 14. 总结

MailGuard 不只是一个返回“垃圾/正常”标签的分类器，而是一个覆盖数据集治理、模型训练评测、在线检测、邮箱接入、AI 复核、可视化解释和安全处置的完整邮件安全系统。它在保证本地机器学习稳定性的同时，引入可控的大模型复核能力，并通过权限、加密、审计和安全默认值降低真实邮件处理过程中的风险。
